# shadcn/ui Setup + Privacy Center Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install and theme shadcn/ui to match Pulse's existing teal/glassmorphism identity, then migrate `/privacy` (`PrivacyCenter.tsx`) onto shadcn's `Button`, `Card`, and `Dialog` as the first proof of the migration pattern.

**Architecture:** shadcn components are added via the CLI into `app/components/ui/`. Theming happens entirely through CSS custom properties in `app/globals.css` (Tailwind 4 CSS-first config — no `tailwind.config.ts`), so shadcn's default component styling picks up this app's teal accent, radius, and high-contrast behavior automatically. `Card` usages additionally layer the existing `.glass-card` utility class (which the CSS-variable approach alone can't reproduce, since it also carries `backdrop-filter`, a layered `box-shadow`, and a hover-lift transform) and neutralize shadcn's own default `bg-card`/`border` utilities via `bg-transparent border-transparent shadow-none` so there is no ambiguity about which background/border rule wins. Data fetching in `PrivacyCenter.tsx` is untouched — this is a presentation-layer swap only.

**Tech Stack:** Next.js 16 (App Router), React 19, TypeScript strict, Tailwind CSS 4 (CSS-first), shadcn/ui (New York style) on Radix UI primitives, Vitest + Testing Library.

**Spec:** [docs/superpowers/specs/2026-08-29-shadcn-feature-flows-design.md](../specs/2026-08-29-shadcn-feature-flows-design.md)

## Global Constraints

- Gradual migration only — no other route's markup changes in this plan.
- shadcn components stay as generated by the CLI; theming happens via CSS variables, never by hand-editing `app/components/ui/*` internals.
- The existing teal accent, glassmorphism card look, and category-color triads (sage/cerulean/terracotta) must be visually unchanged after this plan.
- `AccessibilityContext` (`app/context/AccessibilityContext.tsx`) keeps driving high-contrast/font-scale/dyslexic-font via the existing `body` class toggles (`high-contrast`, `text-large`, `text-xlarge`, `font-dyslexic`) — no parallel theming mechanism.
- No RSC, no Supabase server client, no `middleware.ts` — `PrivacyCenter.tsx` keeps fetching via the browser `supabase` client in `useEffect`, exactly as today (see spec Decision 3).
- No change to RLS policies, migrations, `database.types.ts`, or the k-anonymity/BRI logic tracked separately in Phase 8/9.
- `npm run lint` and `npx tsc --noEmit` must stay clean (per `AGENTS.md`).

```ts

```

to:

```ts

if (typeof window !== 'undefined' && !window.ResizeObserver) {
  class ResizeObserverMock {
    observe() {}
    unobserve() {}
    disconnect() {}
  }
  window.ResizeObserver = ResizeObserverMock as unknown as typeof ResizeObserver;
}

        <div className="py-4 text-center space-y-3">
          <div className="h-12 w-12 rounded-full bg-teal-50 text-teal-600 flex items-center justify-center mx-auto">
            <Check className="h-6 w-6 stroke-[3.0]" />
          </div>
          <p className="font-bold text-neutral-800">Deletion Request Submitted</p>
          <p className="text-[10px] text-neutral-400">Your request has been forwarded to HR for review. Your account will be permanently deleted after the approval and grace period.</p>
        </div>
      ) : (
        <>
          <p>
            You are requesting to permanently delete your mood logs, saved kudos, and settings from this platform.
          </p>
          <div className="p-3 rounded-lg bg-red-50/50 border border-red-100/50 text-[10px] text-neutral-600 flex items-start gap-2">
            <Info className="h-4.5 w-4.5 text-red-600 shrink-0 mt-0.5" />
            <p>
              Deleting your data will reset your Burnout Risk Index, clear any pending messages scheduled for after-hours, and erase your account data. Your request will be reviewed by HR before permanent deletion is executed.
            </p>
          </div>
          <p className="pt-2">Click below to confirm deletion request.</p>
        </>
      )}
    </div>

    {!purgeSuccess && (
      <DialogFooter>
        <Button variant="secondary" size="sm" onClick={() => setShowPurgeConfirm(false)}>
          Cancel
        </Button>
        <Button
          variant="destructive"
          size="sm"
          onClick={handlePurgeData}
          disabled={isPurging}
          className="gap-1.5"
        >
          <Trash2 className="h-4 w-4" />
          <span>{isPurging ? 'Submitting...' : 'Delete All Data'}</span>
        </Button>
      </DialogFooter>
    )}
  </DialogContent>
</Dialog>
```
